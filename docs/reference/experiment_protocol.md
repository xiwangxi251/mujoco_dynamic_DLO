# 动态线缆抓取实验协议

本文定义后续仿真与真机实验的统一口径。研究主问题是：**方法能否根据线缆的整体运动与局部形变，持续完成动态对中、夹持和抬升**。抓后滑脱是必须保留并监测的真实物理失败，但不是本项目的主要优化目标，也不能取代运动类型、难度和泛化实验。

正式实验开始前，应把本文、`src/panda_cable_grasp/scenarios/registry.py` 的场景表、seed
列表、公共成功判定、失败分类、checkpoint 选择规则和样本量一起冻结。冻结后的 OOD
结果不得用于调参、选模型或修改场景。

## 1. 场景因子

### 1.1 四种运动类型

| 类型 | 环境施加的分量 | 要回答的问题 |
| --- | --- | --- |
| `static` | 不施加运动外力；仍保留重力、接触和机器人作用 | 静态抓取下限，以及动力学自然沉降基线 |
| `rigid` | 线缆质心平移与绕质心转动；关闭主动形变分量 | 方法能否追踪整体移动、旋转但形状基本不变的目标 |
| `shape` | 去除净平移和净转动的空间非均匀力场 | 方法能否应对局部连续弯曲，而不是只追踪质心 |
| `combined` | 将shape分量直接叠加到候选L1或L2整体平移/旋转 | 方法能否同时应对局部形变与整体运动 |

“关闭某个分量”是指环境指令严格为零，不代表实际线缆在接触、惯性和桌面摩擦下能做到数学意义上的绝对刚体或绝对静止。因此，场景有效性必须由第7节的真实运动诊断确认，不能只看配置名称。

所有新实验场景使用`factorized_v2`或L1/L2 v2 profile，并按episode seed生成配对的C形、S形或
低频样条型随机弯曲初始构型；只有`legacy_v1`和为读取旧manifest保留的`factorized_v1`继续使用
直线初态。初始曲线随机性与后续shape动态形变是两个独立因子，不能把“初始是弯的”记为发生了
形状变化。

### 1.2 ID中的L1/L2整体运动

每个episode的随机曲线保持所有相邻节点间距不变，并把实际初始节点构型记为本轮模板。
`id_rigid_l1_{low,nominal,high}`从`y=-0.70 m`沿直线单程
匀速运动到`y=+0.70 m`；`id_rigid_l2_{low,nominal,high}`使用相同起终点，沿单段三次
Bézier S形曲线运动，并按曲线弧长设置持续时间，使平均目标速度与L1相同。两者同时绕质心完成
seed决定方向的`±24°`有限旋转；相同seed的L1/L2共享逐节点完全相同的初始曲线、目标段和旋转
方向。`id_combined_l1_{low,nominal,high}`和`id_combined_l2_{low,nominal,high}`分别在
完全相同的L1/L2平移、旋转上直接叠加shape力场；combined中禁止启用固定构型保持力，否则会
抵消要研究的动态形变。运动在`SETTLE=0.8 s`后开始，low/nominal/high目标速度约为
`0.167/0.25/0.375 m/s`，轨迹不折返、不循环。

L1/L2的平移、旋转和rigid专用构型保持力在稳定双指抓取确认期间暂停，防止环境驱动力继续作用并
改变线缆形状，从而破坏“固定形状整体运动”的实验定义。双侧接触连续丢失达到`0.35 s`、或策略
主动张开并解除确认抓取后，整体驱动力恢复；因此该暂停不会消除或掩盖真实滑脱。`shape`和
`combined`实验的局部形变指令不采用此暂停条件，接触后仍继续施加；combined确认抓取期间的总环境
指令严格只剩shape分量，抓取解除后恢复为shape与整体运动的叠加。未处于确认抓取状态且实际质心
到达单程终点时，本轮按运动边界失败结束。

旧的有界准周期整体平移/旋转实现已经删除，原`id_rigid_*`、`id_combined_*`和`pilot_*`名称均不再
注册，不能与新版混用。当前profile版本为
`rigid_level{1,2}_single_pass_v2`。标称档6个配对seed的无策略诊断中，L1/L2实际RMS速度均值为
`0.203/0.202 m/s`（含0.8 s静止），最大转角均值为`23.80°/23.81°`；形状RMS的最坏值为
`0.643/0.621 mm`，单帧最大残差的最坏值为`0.980/0.940 mm`，所有seed的边界修正力均为0。
诊断只验证运动语义，进入L1/L2选择前仍须重新做配对端到端抓取。12个候选场景现在是显式ID
条件并进入`paper`；完成选择后，最终协议仍只从L1/L2中冻结一种，并删除另一组条件。

兼容场景`id_shape_nominal_current`复现旧环境的准周期、去均值形变力场，`disturbance_strength=1.5`。它用于旧代码和checkpoint回归，不代表完整实验矩阵。

### 1.3 幅度、频率和规律性

非静态场景使用三个幅度档和三个频率档：

| 档位 | 扰动强度 | 频率倍率 |
| --- | ---: | ---: |
| `low` | 0.75 | 2/3 |
| `nominal` | 1.50 | 1.0 |
| `high` | 2.25 | 1.5 |

幅度与频率是独立因子。主网格可以先联合改变二者，开发集必须另做单因子扫描，避免把“更快”和“更大”混成一个难度结论。时间规律分为：

- `regular`：严格周期信号；
- `quasiperiodic`：多个不可公度频率及相位调制，短回合内不重复；
- `stochastic`：按episode seed固定的带限随机轨迹，可复现但不在ID训练中出现。

禁止逐物理步白噪声式抖动。它既难以在真机复现，也会把任务变成接触求解器压力测试。

### 1.4 线缆长度与材质OOD

标称线缆参数为：长度0.80 m、半径0.014 m、密度150 kg/m³、弯曲刚度2000、扭转刚度10000、阻尼0.025、滑动/扭转/滚动摩擦`2.0 / 0.08 / 0.01`。半径在当前OOD中保持不变，避免同时改变夹爪几何匹配关系。

当前 OOD 评测只使用 L1 `combined` 基准，并对每个 episode 独立、可复现地
采样一个因素倍率。高区间为 `1.1--1.5` 倍，低区间为 `0.5--0.9` 倍（均相对
对应标称值）：

| 因素 | 高区间场景 | 低区间场景 | 物理含义 |
| --- | --- | --- | --- |
| 形状变化幅度 | `ood_combined_l1_amplitude_high` | `ood_combined_l1_amplitude_low` | shape 扰动幅度随机采样 |
| 频率 | `ood_combined_l1_frequency_high` | `ood_combined_l1_frequency_low` | shape 扰动频率随机采样 |
| 长度 | `ood_combined_l1_length_high` | `ood_combined_l1_length_low` | 编译前线缆长度随机采样 |
| 材质 | `ood_combined_l1_material_high` | `ood_combined_l1_material_low` | 密度、刚度、阻尼和摩擦共同使用同一倍率 |

标称线缆长度为 `0.80 m`，因此长度 OOD 的范围为 `0.40--0.72 m`（低）和
`0.88--1.20 m`（高）。材质 OOD 的四个缩放参数使用同一个随机倍率，以便把
“材质整体变软/变硬”与长度因素分离。每个场景的实际采样值写入逐回合 CSV。

这些必须是通过MjSpec进入编译模型、质量矩阵、弹性插件和接触参数的真实变化，不是只写入CSV的标签。每种配置都应保存实际编译的MJB及参数哈希。真机实验应测量所用线缆的长度、直径、线密度、准静态弯曲响应和表面摩擦代理量，并按实测值建立映射，而不是仅用“软/硬”名称对齐。

## 2. ID、开发集与OOD

- `ID`：定义训练分布与论文ID测试条件。训练可以采样ID场景，但正式测试seed不得参与训练。
- `dev`：只用于环境校准、超参数与checkpoint选择。开发集结果不能作为最终泛化结论。
- `OOD`：训练和模型选择期间完全不可见，包括 L1 上的幅度、频率、长度和材质区间变化。

`src/panda_cable_grasp/scenarios/registry.py` 为每个场景生成稳定的 `scenario_id` 与完整哈希，
并提供五组实验套件：

| suite | 内容 | 用途 |
| --- | --- | --- |
| `core` | `static`、兼容标称`shape`及L1/L2标称`rigid/combined`，共6个场景 | 最小端到端回归和真机核心集 |
| `motion_sweep` | 除core与OOD外的ID难度网格及dev纯形变单因子扫描，共15个场景 | 幅度、频率、规律性和运动类型分析 |
| `ood` | L1配对的幅度、频率、长度和材质高/低区间，共8个场景 | 冻结模型后的泛化测试 |
| `paper` | `core + motion_sweep + ood`，共31个场景 | 当前正式论文全量仿真；冻结轨迹后再缩减 |
| `all` | 与当前`paper`相同，共31个场景 | 全部注册场景，用于开发检查 |

正式表格必须保留`split`、`scenario_name`和`scenario_id`三列。不能把所有场景直接合并成一个平均成功率而不报告分层结果。

## 3. 方法与公平比较

当前统一 benchmark 可执行的方法为：

- `scripted`：基于目标线段预测与点跟踪控制的规则基线；
- `expert`：读取仿真特权状态并搜索未来可抓线段的教师/上界，不是可部署方法；
- `ppo`：当前 99 维完整线缆状态观测、5 维任务空间动作的强化学习接口。
- `diffusion_policy`：双相机 RGB 与末端位姿输入的离线视觉动作扩散策略，使用
  `--diffusion-policy-model` 指定训练 checkpoint。

DynamicVLA 已有独立 ZMQ 在线适配、数据转换、微调和逐回合记录链路。由于一个模型客户端
维护一条有状态动作流，目前不与本地 benchmark worker 共享，而是使用独立入口串行评测；
它仍必须采用相同底层 `task_success`、场景和 paired seeds。视觉方法与状态方法输入不同，
应分组报告，不能称为同观测公平比较。

现有 PPO checkpoint 只覆盖课程中的有限 ID 场景，并非按最终冻结的完整 ID 矩阵从头训练。
它们可用于回归和方法开发，但不能直接作为最终 `paper` suite 模型。最终 PPO 应按预先冻结
的概率覆盖 ID 矩阵，只用 dev 选择 checkpoint，然后一次性运行 ID 盲测和 OOD。

调研中建议的 π0.5 目前没有本项目的训练数据、checkpoint 或统一接口，因此仍列为待实现方法。
Diffusion Policy 已有训练/评估接口，但正式结果仍必须先使用本项目数据训练 checkpoint，
不能填入推测值、其他任务论文数值或由脚本策略冒名生成的结果。它必须使用相同动作频率、
机器人/夹爪约束、公共 `task_success` 和 paired seeds。

## 4. Seed配对、重复次数与运行顺序

对每个`scenario × seed`，所有方法必须共享：

- 初始线缆平移与动力学状态；
- 运动相位、空间相位和带限随机轨迹；
- 目标线段；
- 线缆物理参数及编译模型。

运行器必须校验`scene_fingerprint`、`scenario_id`和`motion_profile_hash`。方法可以按任意顺序运行，但seed集合不能因某个方法提前失败或运行较慢而改变。若某回合因程序错误中断，应对该`scenario × seed`的所有方法一起重跑，而不是只补一个方法。

推荐样本量：

- pilot：每个core场景10个seed，只用于排错、估计耗时和校准运动范围；
- dev：每个候选配置至少20个固定seed；只做模型选择，不进入最终表；
- 正式仿真：每个`method × scenario`至少100个从未参与调参的paired seed；
- 真机：先用core中有代表性的条件做每方法每场景至少20次，资源允许时30次；采用随机区组顺序，并把日期、操作者、线缆实例和设备重置作为区组信息记录。

pilot后可根据方差做功效分析并提高样本量，但不能看完正式结果后减少样本量或挑seed。正式seed列表应在运行前写入只读清单。

## 5. 主指标与统计口径

唯一论文主指标是环境公共判定`task_success`：当前仍需真实双侧夹持、被抓线段高度、整线离桌比例、夹爪闭合和中心距离同时连续满足0.80 s。方法内部的`policy_success`、阶段状态或奖励只用于诊断。

每个`method × scenario`至少报告：

- `task_success / N`与95% Wilson双侧置信区间；
- 与基线在相同seed上的成功/失败四格表，以及McNemar检验或paired bootstrap差值区间；
- 成功时间、首次双侧候选时间、首次确认抓取时间、峰值抬升和动作饱和率等次指标；
- 按运动类型、幅度、频率、规律性、ID/dev/OOD、长度和材质分层的结果。

跨场景总平均只能作为补充。建议同时用场景为固定效应、seed为配对区组的二项模型或分层bootstrap，避免大场景组在简单平均中获得更高权重。

### 5.1 互斥失败类型

失败回合按公共因果分类只计入一个主类别：

1. 从未形成双侧候选；
2. 形成候选但未确认抓取；
3. 确认抓取后主动张爪；
4. 确认抓取后闭爪物理滑脱；
5. 接触已丢失过程中张爪；
6. 已确认抓取但未满足完整任务成功。

分类使用最早的确认抓取后断开原因。成功后掉落不能被历史成功掩盖；若回合滑脱后重新抓住并最终成功，则主结果仍为成功，同时在“发生过物理滑脱”的事件列中保留。主表报告所有失败类型的计数和占失败比例，不能只挑一种失败讨论。

### 5.2 滑脱是附加约束，不是主目标

真实摩擦模型允许物理滑脱。项目不追求“零滑脱”，也不能通过粘附、焊接、隐藏跟随力、降低抓后扰动或扩大夹爪碰撞范围消除它。附加验收仅检查：在预先指定的正式评估集合内，令

- `x`为`physical_slip_after_confirmed_grasp`失败数；
- `n_F`为全部`task_success=False`的回合数；
- `p_slip=x/n_F`。

对`p_slip`计算二项分布**单侧95% Wilson上置信界**（`z=1.644854`），要求其上界严格小于0.5，才有证据说明滑脱没有主导失败构成。若`n_F=0`则该比例记为N/A；若失败样本过少导致上界不低于0.5，应增加预先定义的独立seed，而不是根据点估计宣布通过。

这个检查是环境与方法行为的诊断门槛，不是checkpoint选择指标，也不是围绕滑脱反复调奖励的理由。若未通过，应先区分运动场过强、接触参数失真、策略抓后动作过激和策略主动开爪，再决定修正哪一层。

## 6. 真实运动诊断

每次场景定义或物理参数改变后，先在机器人保持 ready 姿态时运行
`panda-cable-motion-diagnostics`，再运行抓取实验。诊断同时记录：

- 施加的shape、rigid translation、rigid rotation和软边界加速度RMS；
- 线缆质心位移、路径长度和速度；
- 相对初始构型的平面刚体旋转角；
- 经过质心平移与最优刚体旋转配准后的形状残差RMS。

对L1/L2还应逐seed检查初始曲线族、目标总转角和扫掠边界，并要求配准后形状RMS低于`1 mm`；
该阈值用于验证“形状不变”的数值实现，不代表把线缆换成刚体或冻结MuJoCo状态。
combined发生明显形变后，单个Kabsch转角会混入线缆主轴随形变产生的变化，因此只能作为响应描述；
验证L1/L2是否正确叠加还必须同时检查平移/旋转命令轨迹及分解后的刚体驱动力，不能仅看Kabsch角。

示例：

```powershell
panda-cable-motion-diagnostics `
  --suite core --seeds 10 --seconds 8 --sample-hz 10 --seed 20280804
```

四种场景至少应满足以下语义检查：

- `static`：三个主动运动分量均为零，实际运动位于自然沉降基线内；
- `rigid`：刚体分量非零、shape分量为零，质心/旋转显著高于static，同时形状残差明显低于shape；
- `shape`：shape分量非零、刚体分量为零，配准后形状残差显著高于static；
- `combined`：两类指令分量均非零，实际整体运动和形状变化都高于static。

pilot阶段应用多seed分布冻结数值阈值。若软边界加速度成为主要分量、线缆频繁撞桌边、某档运动不可区分，或标签与实际运动不一致，应先重新校准环境；不能直接进入方法比较。正式运行时保存诊断CSV和manifest，使“幅度更大/频率更高/发生形变”等结论都有实际轨迹依据。

## 7. 真机环境完善

真机不应只复刻一个“有人晃线”的不可复现实验。推荐逐步补齐：

- 可编程XY平移与转台，用于可重复的整体平移/旋转；
- 独立的多点或端点驱动机构，用于局部形变；组合条件同时启用两套驱动；
- 顶视相机加腕部相机，记录线缆中心线、夹爪中心和接触前后轨迹；必要时在线缆上加轻量视觉标记，但需验证标记不显著改变弯曲与摩擦；
- 末端六维力/力矩、夹爪开度/电流和驱动器编码器同步记录；
- 统一硬件触发或时间戳，保存原始视频、控制命令、机器人状态和每次人工重置记录；
- 桌边防坠网和急停只用于安全，不参与任务成功，也不得把线缆导回夹爪。

仿真与真机的运动应通过质心轨迹、旋转角、配准后形状残差、频谱和速度分布对齐，而不是要求驱动器力命令数值相同。真机先执行core，再选幅度/频率各一档和长度/材质OOD代表条件；只有core流程稳定后才扩大全矩阵。

## 8. 推荐执行顺序

1. **Pilot环境校准**：运行四种运动的无策略诊断；每个core场景10个seed；检查稳定性、可区分性、边界占比和日志完整性。并用脚本基线做小样本端到端运行，但不据此声称方法优劣。
2. **冻结协议**：冻结场景注册表及哈希、物理参数、诊断阈值、成功/失败定义、seed清单、样本量、训练分布、checkpoint选择规则、代码/XML版本和统计脚本。
3. **正式仿真**：在ID矩阵从头训练PPO；只用dev选checkpoint；冻结模型后用相同paired seed运行`paper`，先报告逐场景结果，再报告分层汇总和OOD差距。现有legacy PPO只能列入回归附录。
4. **真机实验**：用仿真冻结后的方法和公共判定执行随机区组实验；先core后代表性sweep/OOD；记录任何人工干预、设备异常和安全终止，并按预注册规则处理缺失回合。

任何阶段发现代码错误，都应修复后更改协议版本并重跑受影响的全部方法/seed；不能只重跑表现不佳的方法。

## 9. 每次正式运行必须归档

- `episodes.csv`：逐回合公共成功、内部成功、失败类型、场景字段、seed、时间和诊断指标；
- `manifest.json`：命令、依赖、操作系统、MuJoCo版本、代码/XML/checkpoint哈希、场景完整配置和seed规则；
- 每个真实物理配置的编译MJB及哈希；
- motion diagnostics CSV/manifest；
- 固定比例的成功与各类失败录像，正式统计出现异常时保留全部原始状态；
- 汇总脚本生成的置信区间、paired比较和失败构成结果。

禁止只保存均值、覆盖旧运行目录、手工删除失败回合，或把方法内部成功当作公共`task_success`。
