# PPO 近桌面高速碰撞：调研与当前执行层诊断

日期：2026-10-04。用户要求调研；本记录是工程建议，未修改训练、执行器、奖励或物理参数。此前已确认的优化点 1（成功 ±2、首次位置奖励 ±4）仍独立记录于 `target_node_ppo.md`。

## 结论

建议采用：近桌面按距离和实际速度提前减速 + 考虑制动能力的执行约束 + 动作加速度/jerk 限制 + 训练与部署使用相同保护。碰撞奖励用于学习偏好，不能作为唯一保护。阻抗、导纳及力矩监控用于处理不可避免的接触及模型误差。

## 当前代码确认的事实

检查对象：`outputs/rl/train/ppo_targetnode_full6_workspace_20261004/full6_workspace_env.py` 及同目录 `frozen_code/src/panda_cable_grasp/`。这不是一次新的模型测试，以下是代码与配置诊断。

- PPO 平移输出先限制三维范数，再乘 0.01 m；20 ms 控制周期，进入 JIK 的平移请求最大 0.5 m/s。
- JIK 的线速度 cap 为 0.9 m/s、角速度 cap 为 1.4 rad/s；下游命令限速为线速度 0.9 m/s、角速度 2 rad/s。
- 执行器臂 kp×4、kv×2，重力前馈有界。`q_target=q_actual+0.11*qdot`。
- 关节命令加速度限制显式关闭，没有专门按桌面净空变化的下降速度约束。
- 桌面手指过滤启用，通用 geometric safety 关闭。
- `_project_table_safe_target()` 通过替换关节位置和 `mj_forward()` 检查目标姿态；检查手指 mesh 与桌面接触，余量仅 0.0002 m。它不是包含惯性、速度、制动能力的动态安全预测。距离实现只遍历接触列表，不是任意净空下的连续距离查询。
- 源码注释明确说明：目标姿态投影不能消除 PD 跟踪和惯性已经造成的接触，碰撞后使用向上恢复目标。
- 实际手指桌面穿透按控制步扣 0.05，过滤触发按步扣 0.02；两者共用每回合 2 分上限，前 5000 环境步逐渐启用。不根据碰撞前法向速度、冲量或接触力分级。
- 示例：0.5 m/s 持续 20 ms 对应 10 mm 位移，明显大于 0.2 mm 的过滤余量。这只是量级比较，不代表已测得此次视频的碰撞速度。

推断：保护缺少提前制动、较高位置刚度可能加剧接触冲击、速度无关且封顶的惩罚可能不足以改变策略行为。这些是待验证的原因；视频观感不能代替实际接触点速度和力的数据。

## 调研得到的主要路线

### 1. 根据障碍距离减速，并在执行层拦截危险动作

MoveIt Servo 官方文档描述了接近碰撞时的速度缩放，以及运动平滑和关节速度/位置限制。RL 文献中的安全过滤器进一步用控制屏障函数（CBF）、QP 或可达性分析约束策略输出。

- [MoveIt Servo](https://moveit.picknik.ai/main/doc/examples/realtime_servo/realtime_servo_tutorial.html)
- [Acc-CBF-QP，IROS 2026 作者项目页](https://safe-rl-qp.github.io/)
- [Safe RL of Dynamic High-Dimensional Robotic Tasks](https://arxiv.org/abs/2209.13308)
- [Sim-to-Lab-to-Real](https://saferoboticslab.github.io/SimLabReal/)

针对本项目：使用每个可能碰桌的机器人表面点到桌面的净空 d，以及该点的法向接近速度。应包括手指、掌部和可能靠近桌面的连杆，不只检查 TCP。表面点速度包含旋转项 `v_point = v_TCP + omega × r`；TCP 很慢也可能因旋转而让指尖很快。

先做下降方向速度约束，接近桌面时渐进降低下降速度；向上离开应可正常执行。低净空下也要约束横向擦碰和旋转扫碰。对于复杂方向耦合，可在 JIK/QP 中加入各表面点的距离变化约束，再在最终执行目标处复核。

### 2. 减速必须考虑刹车距离

简单一维制动设计的参考关系：

`d_required = margin + v_down * latency + v_down**2 / (2 * a_brake)`

其中 v_down 使用实际表面点接近速度；latency 包括感知、通信和控制延迟；a_brake 是当前姿态/载荷下可保守保证的有效减速度；margin 覆盖标定、几何和跟踪误差。

例如 v_down=0.5 m/s、latency=0.02 s、a_brake=1 m/s²，延迟与制动距离合计 0.135 m，尚未加 margin。该例仅说明不能到距离几毫米时才停；这些数字不是 NERO 厂商安全限值。多关节耦合、jerk 和扭矩饱和需要更完整的预测与约束。

单纯 `v_down <= k*(d-margin)` 是运动学约束，不能自动保证有惯性的真实机器人能够立即满足它。QP 的保证也依赖模型、延迟假设、控制能力和问题可行性，需要明确不可行时的受控制动策略。

### 3. 命令平滑、加速度/jerk 限制和适当柔顺

MoveIt Servo 提供多种平滑器；官方明确说明普通低通滤波不等于显式限制加速度或 jerk。阻抗相关 RL 工作则比较了位置/力矩/可变阻抗动作空间，支持在接触任务中采用结构化柔顺控制。

- [Learning Variable Impedance Control for Contact Sensitive Tasks](https://arxiv.org/abs/1907.07500)
- [VICES 作者项目页](https://stanfordvl.github.io/vices/)
- [接触技能的仿真到真机导纳适配，CoRL 2023](https://arxiv.org/abs/2310.10509)

针对本项目：先加入可实现的加速度/jerk 限制，并在仿真训练中使用；评估近桌面降低有效位置刚度、限制跟踪误差和力矩、保留必要阻尼与重力补偿。kp×4、kv×2 并不直接证明阻尼不足，但同等位置误差下更大的 kp 会产生更大的位置恢复力矩。变刚度本身也需要平滑和稳定性验证。

### 4. 奖励、约束和训练分布配套

建议奖励重点惩罚近桌面过大的实际接近速度，及真正发生的机器人桌面撞击；碰撞强度可用碰撞前速度、峰值力、冲量辅助区分。这里的奖励设计是本项目建议，不是上述论文统一使用的公式。

- 距离加权的超速惩罚应在接触前提供信号，不把远离桌面的正常运动一起强烈惩罚。
- 过滤器频繁介入可设轻量训练代价，减少策略依赖保护层硬顶边界。
- 碰撞惩罚需检查相对任务奖励的量级和封顶后是否失去持续约束；严重冲击可终止回合，轻微接触可分级处理。
- 排除线缆正常接触桌面的情况，区分机器人碰桌、抓取线缆和物体桌面接触。
- 训练从一开始执行同一保护，已有 checkpoint 可作为诊断或微调起点；直接在部署时新增强过滤会改变策略闭环行为，必须重新验证任务效果。
- 观测应提供可部署的桌面净空和接近速度；桌面平面可以标定，机器人几何距离可以由编码器与 FK 计算，无需依赖真机无法获得的仿真接触真值。
- 用实测参数校准控制响应，再随机化桌面高度误差、载荷、延迟、传感噪声和接触参数；域随机化不能代替运行时保护。

## NERO 真机接口边界

[AgileX 官方 Nero API](https://github.com/agilexrobotics/pyAgxArm/blob/master/docs/nero/nero_api.md) 提供 MIT 的期望位置、期望速度、kp、kd、前馈力矩接口，也列出关节/法兰速度和加速度限制、碰撞保护等级。具体参数和反馈行为依赖固件与控制模式，需读回验证；文档列出接口不等于已确认用户设备在 MIT 模式下所有限制都生效。

## 建议实施顺序和核查指标

1. 先在保存/新增诊断轨迹中记录每个风险表面点净空、碰撞前法向速度、TCP/关节实际速度、位置跟踪误差、接触峰值力/冲量和保护介入率，定位冲击来自平移、旋转、过冲还是桌面/几何误差。
2. 给当前执行层加提前减速、刹车距离约束、动作加速度/jerk 限制；同时评估抓取可达性和任务成功率，避免过大余量把近桌面的线缆变成不可抓。
3. 将相同控制层用于仿真训练，必要时再加针对冲击的奖励；柔顺和力反馈保护与硬件接口能力匹配。
4. 对比成功率、碰撞次数、接触前速度分位数/最大值、冲击峰值、净空约束违例和过滤器介入率；不能只凭视频变慢或总回报改善认定可上真机。

本调研尚未做新的控制器实验，也未确认具体 NERO 实机的固件、模式、可保证减速度和力阈值。
