# 指定点PPO：松爪后继续扣回抬升收益

后续又统一了v6正奖励和承载确认的接触宽限，见[抬升奖励接触宽限](target_node_lift_contact_grace.md)；
下文“当前双侧接触”描述的是该后续修正之前的正奖励资格，收益扣回算法继续保留。

## 问题与修正（2026-10-06）

4999200步旧v5录像中804和805的节点及线缆比例抬升净奖励分别为1.6895、2.1941，掉落后未扣回。原累计曲线确实下降，但主要来自接近、对齐分项。v6仍继承该问题：正负进度共用当前夹持资格，失去接触后不扣下降，物理基准却更新，后续无法补扣。

默认`tolerance_progress_v6`现在标记为`lift_progress_accounting_version=physical_node_release_bounded_debit_v2`。正奖励仍要求当前确认夹持、双侧接触、有效开度与中心距离，且只支付整回合历史最高值以上的新进度。每笔实际支付记录物理节点、支付的高度区间及当时目标节点折扣；线缆抬起比例单独记录对应区间。

每步无论夹持是否存在、当前节点是否改变、目标匹配是否合格，都观察此前支付节点及比例的实际回落，扣回支付区间内已消失的部分。每笔扣回沿用原支付折扣，仅能扣一次，不能超过此前实际支付额。其它节点无奖励的下降不扣节点抬升收益。外力无夹持抬升不领正奖励，也不生成扣回债务；它仍推进整回合高水位。部分下降后反弹到旧峰值不补发奖励，再下降到同一高度不重复扣。

对于目标±2节点，创新高1cm奖励+0.4，持续夹持或松爪后消失的同一已支付1cm均扣−0.4。比例创新高10个百分点奖励+0.3，同一已支付比例消失扣−0.3。偏3/4节点的正奖励折扣0.5/0.25，也用于对应支付区间扣回。高度计奖上限18cm、比例上限30%不变。

v2～v5显式旧配置保留旧算法；历史录像和冻结代码不覆盖。v6冻结提交与账本版本必须一起记录，不能只用profile名称区分修正前后。

## 范围

这次修正节点抬升与线缆抬起比例两项收益，不改变首次接触、捏住、抓取位置等事件奖励。两项抬升进度落回原位净收益应为0，累计总回报仍包含其它事件奖励及成本。未新增观测、动作、强制上抬或松爪处罚，公共成功和物理标准不变。

新训练保存策略、价值网络、优化器、配置和课程，从当前最新完整checkpoint续训，累计预算仍20M。保持109维观测、5维动作、普通PPO、cable_x075_v1矩形区X0.60～0.84/Y−0.22～0.30/Z−0.005～0.10m、增强6+有界DLS、新保护开启、旧过滤器关闭、接触缓存、48训练/13评估worker。课程阶段保留，新奖励下重新积累晋级评估历史。
