# 指定点 PPO 接触读取缓存与 NUMA 放置

## 范围

增加接触读取缓存和可选 Linux NUMA 绑核。保持 24 个训练环境、13 个评估环境、
NoSlip、物理步长、求解器、碰撞参数、奖励及新碰桌保护。继续使用原 84 格工作区掩码。
代码和 151 训练均使用 dev 分支，历史训练源码快照、权重和结果保留。

## 接触缓存

`env/contact_cache.py` 只在环境的受控 `step()` 调用范围内共享读取结果。
底层环境与 RL 包装器共用嵌套范围。每个物理子步、实际模型的 forward 和状态复制
之后重新读取；退出范围或异常时清空。直接在 step 外修改状态后读取不会命中旧缓存。
每次返回新的列表，调用者不能改坏已缓存数据。
`--no-contact-read-cache` 可关闭训练缓存进行对照，实际开关写入训练配置。

## NUMA

`--worker-affinity numa` 根据允许的 CPU 集合和 Linux sysfs 拓扑选择每个物理核的
一个逻辑 CPU，跨 NUMA 节点交替分配；learner 使用剩余独立物理核。
完整计划在缩小父进程 affinity 前传给 spawn 子进程。训练和评估复用核位，
learner 在全部子进程创建完成后才绑核，避免启动导入阶段的子进程挤在一个核上。
两者本来交替运行。worker 在创建 MuJoCo 模型和数据前绑核，使首次分配的内存
尽量就近；没有强制 membind。默认 `none` 便于历史复现，Windows 不启用此选项。
配置保存 learner、训练和评估核号。绑定不改变 seed、环境数量或训练批次。

## 2026-10-05 独立测试结果

750 个策略步含实际夹持和一次回合重置：缓存关闭/开启的物理状态、观测、奖励及
夹持判定完全一致，最大数值差为 0。原始接触扫描从 13183 次降到 7504 次。
24 环境的三组短吞吐量分别为：无缓存/不绑核 78.3，有缓存/不绑核 89.0，
有缓存/绑核 80.8 策略步/秒；三组观测和奖励摘要完全相同。
测试与原训练并行，吞吐量受资源竞争影响，不能把一次差值当成稳定收益。
当次绑核还暴露父进程过早缩小 affinity 的启动开销，已改为子进程全部就绪后绑定。
暂不在正式续训中启用 NUMA，保留为可选实验项。缓存可作为后续续训采用的修改。
