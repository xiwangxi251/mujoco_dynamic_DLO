# Image perception on the previously evaluated 12,797,952-step PPO

User request: on server 151, connect the existing RGB-D node estimator to the
currently training PPO's previously evaluated checkpoint; initially evaluate
20 episodes per scenario and report the success-rate change.

The selected checkpoint is the saved `checkpoint.zip` from
`outputs/rl/train/ppo_session_height_ordered_scratch_20m_20261011/consolidation_20261012/evaluation50_20261012/`.
It contains 12,797,952 cumulative steps and has SHA256
`0c2139526fff87b2862c6e8e800f0ffb3ba74240e97c668d54ca0e10b1b9fe37`.
The original evaluation used source commit
`302132f217c4ba454c9da5d729b3a6ffe0966fc5`. The subsequent training process is
independent of this evaluation; no training process or its source is modified.

The evaluation preserves that source in a Git archive, the original complete
training configuration, evaluation motion bank and workspace hash. It runs
deterministic inference with the original 99-dimensional observation and
five-dimensional action interface. Only the observation's 14 world-frame node
positions and velocities are replaced by `ImgStack` using `img_unet_hist`.
Velocities are frame differences; previous predicted maps are fed back, and
failed extractions retain the previous estimate (initially zeros), never GT.
The original policy TCP transform/scaling, reward, execution, physics and public
`task_success` criterion are preserved. GT is read for error diagnostics only.

Seven original scenarios are evaluated using seeds 20260804–20260823,
20 each, totaling 140 formal episodes. All moving scenarios use full difficulty;
the two static scenarios use zero motion difficulty. Historical GT outcomes on
these same seeds form the paired reference. Before launch, a complete GT
episode in every scenario must reproduce the saved success, step count and
return, followed by a three-step perception smoke in every scenario. Smoke
episodes remain outside formal counts. An intentional worker failure checks
supervisor failure reporting before formal launch.

The runner is `tools/experiments/evaluate_saved_ppo_img.py`; server output is
`outputs/rl/eval/ppo_perception20_12797952_20261013/`.
Its `manifest.json` stores source/configuration/checkpoint/bank hashes, and
`status.json` distinguishes startup, real progress, heartbeat and failure.
Per-episode records include public success, paired GT success, ordered and
flip-tolerant node error, missing estimates and inference latency.
`comparison.json` is complete only when all seven scenarios have 20 records.

This is a limited paired perception-transfer evaluation, separate from the
paper's frozen point-cloud PPO benchmark. It imposes no artificial latency:
physics advances at 50 Hz simulation time while rendering/inference determines
wall-clock speed. No claim about real-time hardware deployment is established.
