# Shape replay：接触不等于阻挡（2026-10-13）

用户指出上一版“碰一下就暂停”不合理。该反馈成立：单侧触碰、擦碰和滑动接触
本来应由物理引擎处理，不能仅凭接触就改变回放进度。当前 Shape replay 改为
`continuous_ff_v4`，替代 v3 的即时接触暂停规则。

## 当前判断

未确认抓牢时，以下条件必须同时连续满足100毫秒，才判为实际阻挡并暂停驱动
与回放时钟：

1. 存在左右手指或夹爪基座与线缆的实际接触。
2. 接触材料节点的参考平面速度均方根至少0.03m/s，排除轨迹自然停顿/低速。
3. 实际速度在参考运动方向上的推进比低于25%。
4. 接触材料节点沿参考运动方向的落后量超过5mm。

推进比由各接触材料节点的实际速度与参考速度投影计算；同一节点的重复碰撞对
只计一次。参考速度包括整体平移和转动，COM静止而线缆旋转受阻也可识别。
位置落后也按运动方向计算，横向偏差或已经领先不作为落后。
任一条件中断就清除候选计时；一串不连续的擦碰不积累成一次持续阻挡。

这些是当前工程判据，尚未通过全库抓取实验校准。短暂碰撞继续正常力驱动和
物理积分，不冻结时钟、不重锚参考；持续接触但仍能正常沿参考方向运动也不暂停。
本次没有改变轨迹、控制增益、物理材料、抓取确认或成功判据。

## 恢复

只有已经确认的持续阻挡才启用恢复滞回：记住触发时的实际碰撞几何对，待其
间隙大于2mm且连续40ms没有新的夹爪接触或原障碍近邻证据后，重锚到当前实际
位姿并从冻结进度续走。该间隙检查不会让初次靠近或擦碰暂停。

实际求解器检查发现，驱动卸力后碰撞对可因微小弹开而消失，但障碍仍挡着路径。
只看碰撞对消失会导致假解除和重复启停，因此恢复时补充实际几何距离检查。
确认抓牢仍沿用公共抓取暂停规则；松开后的速度渐入没有在本次加入。

## 验证与身份

- 状态机和运动学单元检查：短碰、长期正常滑动、连续受阻证据/计时重置、低速
  参考、领先、转动受阻、历史版本兼容。
- 最小真实MuJoCo接触模型：滑动物体撞上固定夹爪障碍，首次碰撞不暂停；20ms
  短碰后移开障碍，时钟保持连续；持续顶住才暂停，障碍不移开时保持暂停，移开
  后不补偿等待时间。这是独立接触/控制夹具，不是机器人抓取成功率实验。
- Panda/NERO完整模型：初始构造真实单侧手指接触，20ms短碰不暂停、不重锚；
  随后去除接触仍继续正常步进。回放测试夹具中的位姿设置直接移动线缆。
- 复用跟踪精度、已抓牢暂停/重锚、时间导数、角度跨界等积分回归；无接触时
  v4/v2的qpos、qvel及回放时钟要求逐步完全一致。

结果位于工作区 `outputs/shape_replay_obstruction_refinement_20261013/`。
最终回归共112项测试、20个子检查通过（163.81秒）。最小物理夹具在0.302秒首次
接触、0.454秒确认持续受阻，参考时钟保持0.454秒；0.800秒移开障碍，0.840秒
恢复，仿真到0.850秒时参考时钟仅走到0.464秒，没有补偿暂停时间。逐步记录见
`physical_trace.json`。
早期 `physical_tests.xml` 保留了卸力后误解除的失败证据；最终回归包含修正后的
持续阻挡检查。没有重跑全库或抓取成功率评测，不把上述夹具检查表述为真实策略
全部接触情形已经验证。
