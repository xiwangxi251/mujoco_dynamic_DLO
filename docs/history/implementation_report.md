- 每轮随机改变线缆位置和形变相位；
- 可视化默认持续运行，关闭窗口后才退出。

## 5. MuJoCo 场景设计

### 5.1 场景包装方式

最终 XML 通过：

```xml
<include file="panda.xml"/>
```

复用官方 Panda，并注册官方 cable 插件：

```xml
<extension>
  <plugin plugin="mujoco.elasticity.cable"/>
</extension>
```

Python 加载模型前还显式加载：

```python
mujoco.mj_loadPluginLibrary(... / "plugin" / "elasticity.dll")
```

这样可以避免 Windows 环境中插件未自动注册导致模型加载失败。

### 5.2 场景内容

XML 中新增：

- 主方向光和辅助方向光；
- 渐变天空盒；
- 棋盘纹理桌面；
- 桌面边界；
- 线缆抓取位置标记；
- 官方 composite cable。

仿真设置：

```xml
<option timestep="0.002" integrator="implicitfast" gravity="0 0 -9.81"/>
```

即：

- 时间步长：2 ms；
- 积分器：`implicitfast`；
- 重力：标准地球重力。

### 5.3 最终线缆参数

线缆定义：

```xml
<composite prefix="cable"
           type="cable"
           curve="s"
           count="41 1 1"
           size="0.8"
           offset="0.23 0 0.045"
           initial="free">
```

主要参数：

| 参数 | 最终值 | 说明 |
| --- | ---: | --- |
| 名义长度 | 0.8 m | composite `size` |
| 节点配置 | `41 1 1` | 编译后识别到 40 个 cable body |
| 半径 | 0.014 m | capsule 半径 |
| 密度 | 150 kg/m³ | 降低线缆重量，便于演示抓取 |
| 关节阻尼 | 0.025 | 抑制高频数值震荡 |
| 接触维数 | 3 | `condim="3"` |
| 线缆自身摩擦 | `2.0 0.08 0.01` | 保留线缆—指垫的高摩擦 |
| 桌面—线缆专用摩擦 | `0.12 0.12 0.003 ...` | 40 个显式 contact pair，避免桌面接触继承线缆高摩擦 |
| twist | `1e4` | 扭转参数 |
| bend | `2e3` | 弯曲参数，经过多轮降低以增加柔软度 |
| vmax | `0.08` | cable 插件速度限制参数 |

桌面摩擦最终为：

```xml
friction="0.35 0.05 0.01"
```

降低桌面切向摩擦可以减少线缆被桌面粘住后只滚动、不弯曲的问题。

## 6. 线缆连续形变实现

### 6.1 初版问题

初版仅使用较弱的横向正弦力。实际视觉效果接近：

- 整根线缆横向滑动；
- 局部曲率变化不明显；
- 桌面压制了竖向形变；
- 线缆看起来偏硬。

### 6.2 最终空间力场

最终 `apply_cable_disturbance()` 沿线缆归一化坐标 `s∈[0,1]` 构造多频率力场。

横向分量由三个空间频率组成：

```python
1.60 * sin(4πs - 1.25t)
+ 1.00 * sin(9πs + 0.82t + 0.5)
+ 0.55 * sin(15πs - 0.48t + 1.1)
```

竖向分量由两个空间频率组成：

```python
1.00 * sin(2πs + 1.05t)
+ 0.55 * sin(7πs - 0.70t)
```

每次计算后都会减去所有节点的均值：

```python
lateral -= lateral.mean()
vertical -= vertical.mean()
```

这一处理很重要。它使外力主要产生节点之间的相对运动和弯曲，而不是给整条线缆一个同方向合力。

最终力幅：

```python
force_y += mass * 7.5 * lateral
force_z += mass * 14.5 * vertical
```

最终表现为：

- 低频大尺度 S 形；
- 中频局部弯曲；
- 高频小尺度波纹；
- 部分节点暂时离开桌面形成拱起；
- 形状随时间连续变化。

抓取前最终验证中，线缆最高点达到约 `0.148 m`；静止线缆中心高度约为 `0.014 m`，说明最终形变已经不是简单滚动。

## 7. Panda 运动控制

### 7.1 模型初始化修正

官方 Panda `home` keyframe 只包含 Panda 的关节状态，不包含后来加入的 cable free-joint 完整初始状态。

直接执行：

```python
mujoco.mj_resetDataKeyframe(..., "home")
```

曾导致 cable 的自由关节位置被 keyframe 中的默认零值覆盖，线缆 XML 中的 `offset` 看似失效。

最终初始化方式为：

1. `mj_resetData()` 恢复完整 `qpos0`；
2. 仅把前九个 Panda/手指 qpos 替换为 home keyframe；
3. 设置八个执行器控制值；
4. 调用 `mj_forward()`。

这样可以同时保留 Panda home 姿态和线缆初始位置。

### 7.2 末端控制点

控制点统一定义为 Panda hand body 坐标系中的实际两指夹持中心：

```python
GRASP_CENTER_LOCAL = [0, 0, 0.1029]
hand_position = hand_origin + hand_rotation @ GRASP_CENTER_LOCAL
```

`0.1029 m` 由手指根部 `0.0584 m` 与主指垫局部中心 `0.0445 m` 相加得到。
`hand_position`、点 Jacobian、IK 位置误差、轨迹控制、抓取误差和成功判定均引用这个同一
几何点。INTERCEPT 和 CLOSE 让该中心直接追踪目标线缆段，不再使用旧虚拟点对应的
`-0.036 m` 高度补偿。

### 7.3 夹爪朝向

线缆初始主方向约为世界 X 轴。Panda home 姿态下，手指开合方向不适合横跨线缆。

最终对 hand 目标姿态施加世界 Z 轴 90° 旋转，使：

- 线缆主要沿世界 X；
- 夹爪开合间隙主要沿世界 Y；
- 两指能够从线缆两侧闭合。

### 7.4 阻尼最小二乘 IK

控制器同时计算位置和姿态误差：

```text
任务误差 = [2.2 × 位置误差, 0.7 × 姿态误差]
```

使用阻尼最小二乘：

```text
dq = Jᵀ (J Jᵀ + λ²I)⁻¹ e
```

主要目的不是获得最优轨迹，而是在演示中稳定地执行：

- 接近；
- 跟踪动态线缆；
- 下降；
- 抬升；
- 侧向搬运。

## 8. 抓取机制的演变

### 8.1 纯接触抓取

最初尝试仅依靠：

- Panda 官方手指碰撞几何；
- 手指闭合控制；
- 线缆与手指摩擦。

薄线缆从桌面离开时容易从指垫中滑出。尤其在线缆持续受外力时，接触很难稳定维持。

### 8.2 全节点抓取辅助及其问题

为了先保证任务效果，曾加入“全节点软抓取辅助”：

- 记录全部 40 个线缆节点相对夹爪的位置；
- 机械臂运动时，对每个节点施加跟随弹簧力。

它能保证线缆被抬起，但产生了明显错误：

- 夹爪闭合后形变扰动被设为零，线缆突然停止；
- 整条线缆都被不可见弹簧托住；
- 抬升后夹爪实际接触可能已经为零；
- 线缆没有从抓取点下垂，而是在空中整体漂浮。

日志中曾出现：

```text
after_lift: cable_gripper_contacts=0
grasp_lift_success=True
```

这证明“成功抬起”来自全局辅助，而不是夹爪接触。

### 8.3 最终单点柔性抓取

最终删除了全节点跟随逻辑，改成单点抓取：

1. 扫描 MuJoCo 当前 contact；
2. 查找与左手指或右手指接触的 cable body；
3. 从接触候选中选择距离夹爪控制点最近的一段；
4. 只记录该线缆段相对夹爪的位置；
5. 只对这一段施加柔性弹簧和阻尼；
6. 其余 39 个线缆段不跟随夹爪，继续由重力、弹性和接触动力学控制；
7. 张开夹爪时立即移除单点辅助。

为了避免随机场景中由于离散时间接触采样漏检，在闭爪后期提供受限回退：

- 只有闭爪超过约 1.2 秒后才允许回退；
- 只有最近线缆段距离夹爪控制点小于 0.075 m 才能捕获。

这不是通用物理抓取器，而是用于稳定展示任务效果的局部软约束。

单点抓取力参数：

```python
force = 55.0 * position_error + 1.8 * relative_velocity
force_z += total_cable_mass * 9.81
force = clip(force, -6.0, 6.0)
```

其中：

- `55.0`：单点位置弹簧刚度；
- `1.8`：夹爪与抓取线缆段的相对速度阻尼；
- 重力补偿：支撑整条线缆重量；
- ±6 N：单轴力限幅，防止数值发散。

闭爪后不会再完全关闭形变，而是保留 15% 扰动：

```python
disturbance_scale = 1.0 if gripper_open else 0.15
```

因此抓取点附近保持稳定，而悬垂部分仍会轻微摆动和弯曲。

## 9. 随机多轮任务设计

### 9.1 随机化内容

每一轮调用 `reset_random_trial()`，随机生成：

- 线缆 X 偏移：`[-0.12, 0.12] m`；
- 线缆 Y 偏移：`[-0.14, 0.14] m`；
- 形变相位：`[0, 2π]`。

随机数生成器当前使用固定种子：

```python
np.random.default_rng(20260804)
```

因此不同试次之间有变化，但重新启动程序后会复现同一随机序列，便于调试和对比。

### 9.2 单轮时间安排

一轮仿真时间为 22 秒：

| 仿真时间 | 阶段 | 夹爪状态 |
| ---: | --- | --- |
| 0–3 s | 移动到线缆上方 | 张开 |
| 3–7 s | 跟踪动态线缆并下降 | 张开 |
| 7–9 s | 闭合并检测接触线缆段 | 闭合 |
| 9–12 s | 垂直抬升 | 闭合 |
| 12–18 s | 侧向搬运并保持展示 | 闭合 |
| 18–22 s | 释放、下落和稳定 | 张开 |

22 秒后：

- 恢复 Panda home；
- 重置线缆；
- 生成新的位置和相位；
- 开始下一轮。

## 10. 可视化退出问题修复

初版 `run_grasp.py` 的可视化默认参数为：

```python
duration = 18.0
```

因此程序在墙钟时间达到 18 秒后自动退出，视觉上经常表现为“刚抓住或刚抬起，窗口就关闭”。

最终改为：

```python
duration = 0.0
```

循环条件为：

```python
duration <= 0 or elapsed_wall_time < duration
```

结果：

- 默认持续执行随机抓取；
- 只有用户关闭 MuJoCo 窗口才结束；
- 仍可通过 `--duration` 指定有限运行时间。

## 11. 实施过程中修复的主要错误

### 11.1 XML site 属性错误

早期曾在 `<site>` 上使用不支持的接触属性，导致 XML schema 报错。最终删除了 site 的 `contype` 和 `conaffinity`。

### 11.2 size 内存配置冲突

曾同时指定：

- `memory`；
- `njmax` / `nconmax`。

MuJoCo 3.11 不允许两种内存配置方式同时使用。最终删除 `memory`，保留：

```xml
<size njmax="1200" nconmax="600"/>
```

### 11.3 Panda 网格路径错误

包装 XML 放在项目目录时，官方 `panda.xml` 中的 `meshdir="assets"` 被相对于错误目录解释，出现 `link0.stl` 等文件找不到。

最终将 XML 同步到官方 Panda 目录，并使用：

```xml
<include file="panda.xml"/>
```

### 11.4 Python 模块局部变量错误

函数内部使用：

```python
import mujoco.viewer
```

曾使 Python 把 `mujoco` 识别为函数局部变量，导致前面的 `mujoco.MjData()` 报：

```text
UnboundLocalError: cannot access local variable 'mujoco'
```

最终改为：

```python
from mujoco import viewer
```

### 11.5 MuJoCo 数组维度索引错误

早期把 Python API 的二维数组当作 C 风格一维平铺数组：

```python
data.xmat[9 * body_id : 9 * body_id + 9]
data.xpos[3 * body_id : 3 * body_id + 3]
```

MuJoCo Python 中它们分别是：

```text
xmat: (nbody, 9)
xpos: (nbody, 3)
xfrc_applied: (nbody, 6)
```

最终改为：

```python
data.xmat[body_id]
data.xpos[body_id]
data.xfrc_applied[body_id, :3]
```

### 11.6 抓取高度错误

早期目标高度按 hand body 原点理解，导致实际指尖控制点停在约 0.27 m，而线缆位于约 0.014 m，夹爪无法接触线缆。

最终统一使用指尖控制点，并将桌面抓取目标设置为接近 `z=0`。

### 11.7 夹爪方向错误

初版保持 Panda home 朝向，手指间隙方向与线缆主方向不合适。最终增加世界 Z 轴 90° 旋转，使夹爪横跨线缆闭合。

### 11.8 线缆偏硬、仅滚动

通过以下改动解决：

- `bend` 从较大值逐步降低到 `2e3`；
- `twist` 降到 `1e4`；
- 降低桌面摩擦；
- 使用零均值多频空间力场；
- 增加足以克服桌面和重力的局部竖向力。

### 11.9 抓取后突然停止和整体漂浮

原因是闭爪时扰动被设为零，并且所有节点都连接到夹爪。最终改为：

- 闭爪扰动保留 15%；
- 仅抓取一个接触线缆段；
- 其余节点自由下垂。

## 15. 当前实现边界

当前结果定位为“任务效果演示”，不是研究级抓取规划或严格的纯接触仿真。

主要边界如下：

1. **形变外力是合成力场**  
   它用于制造可控三维弯曲，不对应具体风场、水流或流固耦合模型。

2. **抓取使用单点软约束**  
   已经比全线缆跟随真实得多，但仍不是完全依赖指垫摩擦的纯物理抓取。

3. **存在有限最近点回退**  
   如果闭爪后期漏检接触，距离小于 0.075 m 的最近线缆段可能被选中。若需要严格接触，可删除这一回退。

4. **随机序列可复现**  
   使用固定种子，因此每次启动的随机序列相同。若希望每次完全不同，可改为 `np.random.default_rng()`。

5. **控制器不是通用规划器**  
   当前目标点、阶段时序和 IK 增益针对本桌面场景调节，没有完整碰撞规划、视觉感知和失败恢复。

6. **XML 存在两个同步副本**  
   项目目录中的 XML 是源副本，Menagerie Panda 目录中的 XML 是实际加载副本。修改 XML 后需要同步两者。

## 16. 后续可扩展方向

如果继续提高物理真实性，可以按以下顺序扩展：

1. 删除最近点回退，只允许真实 contact 触发抓取；
2. 用 MuJoCo equality/connect 在运行时创建真正的局部约束；
3. 为 Panda 指垫增加专用软接触几何和各向异性摩擦；
4. 用线缆曲率和速度预测下一时刻抓取点；
5. 增加失败检测和重新抓取状态机；
6. 将合成扰动替换成风场或水动力模型；
7. 记录每轮成功率、接触力、滑移量和抓取点误差；
8. 接入相机和视觉策略，替代直接读取仿真真值位置。

目标线段从中间 50% 的线缆段随机选择，不再恒定为中心节点。策略使用目标位置和线速度
做 0.22 秒前向预测，闭爪前持续三维追踪；失败时最多重新截获两次。抬升、搬运和保持均

策略，`N` 新建随机试次。后续修正明确保留 MuJoCo 原始 `qpos0`，因为它是关节运动学参考

### 16.7 双侧接触夹持与视觉间隙修正

单侧接触不再成为候选，也不会产生对中力。只有左右指垫都与同一线缆段或其相邻离散段建立
真实接触，并连续保持 0.08 秒，才创建可承重的局部柔性夹持。确认后的辅助力在手坐标系中
采用各向异性刚度：沿线缆切向较软，两个夹持法向较硬，因此保留有限滑移和断裂能力。

进一步视觉检查发现单节点仍不能表达指垫宽度，且预设开口会留下可见空隙。最终改为局部三节点
夹持带：中心节点固定到主指垫局部 `X=0、Z=-0.042 m`，相邻节点按线缆 20 mm 静止节距排列，
覆盖约 40 mm 局部线段，同时约束位置与切向。确认后刚度为 `[350, 1000, 600]`，三个节点
分别受有限力，综合误差超过 0.055 m 时断开。

夹爪保持命令恢复为 `0`，但最终开口由真实碰撞决定。环境将 Menagerie actuator8 的位置增益
和闭合刚度等比例提高 1.5 倍，保持原始开闭目标不变。调参后成功判定时总开口约 25 mm，
三节点夹持带误差约 2–4 mm。连续双侧接触丢失
0.35 秒会解除夹持，避免辅助约束在视觉上已经脱离夹爪后继续承重。

### 16.8 抓空后贴桌扫掠：由环境修正，不限制方法动作

最初版本曾在 `dynamic_grasp_policy.py` 中锁定闭爪 XY 并强制垂直撤离。这只能改变当前脚本
基线，不能修复可供任意学习方法使用的环境，因此已经撤销。当前脚本在 `CLOSE` 阶段仍可
继续输出横向目标；`CableGraspEnv.step(action)` 也不会按抓取阶段覆盖机械臂动作，只执行
执行器范围裁剪。

环境侧采用两项修正：

- 线缆自身摩擦恢复为 `2.0`，保证指垫接触仍有足够摩擦；同时为 `table` 与 `cableG0` 至
  `cableG39` 建立 40 个显式 contact pair，将桌面—线缆滑动摩擦单独设为 `0.12`。因此抓空
  后线缆更容易沿桌面滑到一侧，不会因高静摩擦滞留、弯曲并被漏斗式挤入。
- 每次夹爪控制从张开跨越到闭合时，环境快照记录已经位于指间体积内的线缆节点。后续承重
  代理只能由这些节点或其一个相邻节点的持续双指接触激活。闭合夹爪横扫后来碰到的新节点仍
  完整参与 MuJoCo 碰撞，但不能被代理“吸住”或计为成功。模型可以输出任意动作；若它先把
  线缆推到合适位置，只需再次张开、对准、闭合即可形成新的合法抓取尝试。

固定种子验证中，脚本闭爪后曾从约 `[0.538, -0.068]` 横移到 `[0.309, 0.208]`，期间出现
指垫接触，但环境没有创建抓取，最终进入 `RECOVER`。这直接覆盖了原先的扫掠补抓路径。
需要说明：闭合时的“指间资格快照”属于任务/代理语义，不是软指垫有限元物理。若论文要求
完全接触物理，应进一步删除承重代理，改用软指垫几何、接触参数和纯接触力完成夹持。

### 16.9 局部弯折难度与基线成功率校准

单纯等比例放大旧扰动力不能稳定提高难度：固定 12 个随机试次中，倍率 `1.0`、`1.3`、
`1.6` 的完整成功率分别为 25.0%、25.0%、33.3%，更大的整体位移有时反而把目标线段送到
容易截获的位置。因此没有通过修改策略、成功阈值或动作约束来压低成功率，而是重新设计环境
的局部形变谱：横向模式从三组增至四组，空间频率最高提高到 `19.3π`，时间频率最高提高到
`5.2 rad/s`，低频模式加入连续相位调制，并降低纵向整体移动相对强度。

同一组 5 个随机场景、每场景统计 1–8 仿真秒，修改前后指标为：

| 指标 | 修改前 | 修改后（倍率 1.0） |
| --- | ---: | ---: |
| 横向整体跨度 | 0.436 m | 0.330 m |
| 相邻段平均转角 | 8.0° | 10.3° |
| 相邻段转角 90 分位 | 15.6° | 20.4° |
| 目标段平均速度 | 0.307 m/s | 0.435 m/s |

整体跨度减小而局部转角和速度增大，说明提高的是不断变化的局部弯折，而非整条线缆平移。
新波形下固定 12 个随机试次的脚本基线结果为：倍率 `1.0` 成功 3/12（25.0%），倍率
`1.25` 和 `1.5` 均成功 2/12（16.7%）。最终默认倍率设为 `1.5`，使简单脚本基线落在
目标的 0.1–0.3 区间并更接近 0.1。该比率仅用于环境难度校准，不参与策略动作或奖励计算。

### 16.10 防止环境扰动自行把线缆吹出桌面

不能使用坐标裁剪、固定边界或实体围栏，否则机械臂也无法合理地把线缆推出桌外。最终在
`_apply_cable_disturbance()` 内加入只作用于环境合成力场的软边界：

- 从桌边内侧 `0.16 m` 开始渐进生效；
- 节点越靠近桌边，环境自身朝外的加速度分量越多地被反射回桌内；
- 增加有限回正加速度，系数为 `180 s⁻²`；
- 只阻尼朝桌外的速度，系数为 `28 s⁻¹`；
- 不修改 `qpos/xpos`，不覆盖动作，也不创建碰撞墙；机器人接触力仍由 MuJoCo 独立叠加。

使用4组固定种子、每组5轮、每轮20仿真秒，并让机械臂始终保持在不接触线缆的 ready 姿态。
修改前有4/20轮至少一个节点中心越过桌边。最终参数下只有1/20轮出现4.2 mm的轻微中心越线，
小于线缆14 mm半径；20/20轮都没有节点越过超过一个半径，因此没有真正失去桌面支撑或掉落。
由于软边界只改变环境外力且幅值有限，机械臂仍可通过正常接触将线缆推离桌面。

### 16.11 GUI 性能二次优化

性能剖析表明卡顿的首要原因不是渲染显卡：优化前单个50 Hz环境动作平均耗时20.84 ms，
已经超过20 ms实时预算；90%分位为25.06 ms，最大37.98 ms。即使完全不打开GUI，无界面
实时倍率也只有0.95×。500 Hz的10个 `mj_step` 平均占约14.6 ms；逐节点扰动和软边界在
每个控制周期调用40×10次，进一步消耗约3–5 ms。仿真平均存在68.5个接触，最多134个，
闭爪阶段平均耗时25.42 ms。

最终优化包括：

- 缓存40个节点质量、归一化坐标和8组行波的空间相位；
- 一次生成 `40×3` 扰动加速度矩阵并批量写入 `xfrc_applied`；
- 将软边界的位置、穿透、权重、反射和回正计算改为 `40×2` 数组运算；
- 仅对实际进入边缘缓冲带的少量节点调用精确速度查询；
- GUI单帧最大追赶量由500个控制周期降为8个，避免拖动窗口或断点后长时间假死。

曾尝试把双指接触扫描从500 Hz降到250 Hz，但12轮成功率降为0，因此已经撤销；抓取接触
语义继续保持500 Hz。最终平均环境步耗时为15.84 ms，90%分位19.57 ms，最大约26.29 ms，
无界面实时倍率提高到1.25×。固定12轮抓取结果为1/12（8.3%），接近目标的0.1简单基线

仿真时间，达到稳定1×实时运行。

### 16.12 当前分支：删除弹性抓取代理，改为纯碰撞与摩擦

在 `friction-grasp` 分支中，`CableGraspEnv` 的抓取物理被重新实现。已经删除三节点弹簧阻尼
跟随力、线缆重力补偿、局部固定偏移、闭爪资格快照以及基于代理误差的断裂模型。每个物理子步
写入 `xfrc_applied` 的只剩与策略无关的线缆持续扰动；夹爪不再给线缆施加任何跟随外力。

新的夹持完全由 MuJoCo 碰撞求解：Panda 内指垫设为高优先级六维橡胶接触，滑动、扭转和
滚动摩擦参数为 `6.0 / 0.35 / 0.12`，并使用较硬的接触参数。指垫尺寸、位置、姿态、
碰撞盒和视觉 mesh 均保持 Menagerie 原样，没有扩大指垫或增加凹槽；策略必须把直径
28 mm 的线缆准确对准官方约 17 mm 的主指垫。夹爪执行器增益固定为 Menagerie 配置的
5 倍；这些参数与策略阶段和抓取状态无关。桌面—线缆的 40 个显式 pair 仍保持滑动摩擦
`0.12`，没有随指垫摩擦一起提高。

抓取判定也相应简化为只读状态机：夹爪开口不超过 34 mm，左右内指垫对同一局部线段各自
提供至少 0.20 N 法向力，且线段位于指垫中心 55 mm 内；条件连续 0.06 s 后确认，真实双侧
接触连续丢失 0.10 s 后清除。接触节点编号变化不会再被当作抓取断裂。成功还要求接触线段
高于 0.14 m、至少 18% 线缆离桌，并连续保持 0.55 s。

恢复官方指垫几何后的固定三轮回归中，脚本策略三轮均能形成双指接触并完成抬升，但都在搬运
阶段因持续强扰动发生真实滑脱，完整成功率为 0/3。成功判定快照的实际开口约 26.4–26.7 mm，
不再依赖扩大指垫产生的宽容抓取区。这说明当前简单策略需要提高截获精度和搬运稳定性，任务
没有由环境几何替算法兜底。纯摩擦模型不承诺抵抗任意大外力；若强行保证永不脱落，就必须
重新引入粘附或约束，与本次“真实碰撞＋摩擦夹持”的目标矛盾。

### 16.13 当前工作区：浅槽指垫、闭爪稳定性与实际线段锁定

本节取代16.12中关于“当前参数”的描述。指垫外轮廓没有扩大，但碰撞和视觉几何已经改为
五段阶梯浅槽；接触参数为六维接触和 `4.0 / 0.10 / 0.05` 的滑动、扭转、滚动摩擦。
闭爪位置伺服增益和位置偏置使用5倍倍率，执行器最大力范围不变。线缆持续扰动没有降低，
也没有新增吸附、跟随力或隐藏约束。

脚本在随机参考目标之外增加了实际中心线截获：任意线段进入夹持中心18 mm内就锁定该段并
闭爪；闭爪期间若仍有真实指垫接触，会延长确认窗口。确认抓取后若最终滑脱，失败观察阶段
保持闭爪结束，不再主动张开。固定种子20260804的5轮回归均完成抓取和抬升并达到环境成功，
但只有1轮通过脚本额外的搬运/保持成功口径；二者后续需要统一。

人工复核录像后确认，旧回归中的主要掉落发生在额外搬运而非抬升：旧CARRY会前移170 mm、
侧移220 mm并抬高50 mm，其中一轮进入HOLD时仍有114 mm IK误差，控制器继续拉向不可达
目标；另一轮成功后则是RELEASE主动张开。16.14之前曾把CARRY缩小为朝桌面中心横移
80 mm并抬高20 mm，HOLD锁定实际到达位置，成功后保持闭爪结束录像；该中间方案随后
又被16.14的最终定向回归取代。

### 16.14 抓后反馈消融与接触状态滞回

人工复核固定种子录像确认多轮为抓住后竖直滑落。曾实现过根据接触中心线相对夹爪的位移、
积分误差和0.15 s相对速度前馈移动机械臂，但严格检查发现它会让夹爪跟随线缆一起下降，
相对误差变小并不代表承重改善。最终同配置独立消融中，开启和关闭反馈均为5/5严格成功；
关闭后的末端高度为0.157–0.177 m，当前连续成功保持为1.64–1.77 s，未显示反馈收益。
因此正式代码删除了全部抓后比例、积分和速度反馈，只保留抓取前的形状预测与线段截获。

诊断还发现一次所谓断裂发生时，中心误差仅4.8 mm、开口25.4 mm，原始接触仍覆盖左右
两指；只是瞬时法向力低于0.20 N被错误累计为无接触。首次确认仍严格要求双侧法向力阈值，
确认后则以双侧真实碰撞维持滞回，只有真实双侧碰撞丢失0.35 s才清除状态。该修改只修复
状态估计，不施加吸附、约束或额外夹持力。

脚本闭爪已恢复为 `ctrl=0`。标准形变场景的20-seed成对消融中，`ctrl=20`没有改变确认抓取率
（均为18/20），但严格成功率从14/20降至10/20，终局物理滑脱从1/20升至7/20；实际指垫力、
接触穿透和开口差异也没有稳定支持“20可减小过度挤压”。抬升后夹爪中心不得低于闭爪位置
上方140 mm。HOLD只接受当前连续0.55 s举升资格，不以历史
`ever_success` 掩盖后续掉落。固定搬运的干净A/B在同一五个初态比较默认无搬运和朝桌面
中心侧移80 mm/上移20 mm，两组均为5/5严格成功，成功时间与连续保持时长逐次相同；取消
固定搬运没有显示稳定性收益；按后续要求，默认恢复80 mm侧移和20 mm上移。该结果仍需最终录像与
更多随机种子复核，不能直接外推为总体成功率。

`headless_videos/run_20260809_200100_seed20260804/` 保存的是无固定搬运消融录像，不再对应
当前默认配置。恢复固定搬运后的最终录像位于
`headless_videos/run_20260809_200707_seed20260804/`，同一5个初态为5/5严格成功且末帧均保持双指夹持。

### 16.15 延长连续保持并提高名义抬升

在不改变成功高度、整线抬起比例和夹爪距离门槛的前提下，连续成功保持从0.55 s延长到
0.80 s，脚本名义抬升从180 mm提高到220 mm；扰动、固定搬运和夹爪参数保持不变。同一固定
种子20260804的5个初态得到4/5严格成功。trial 3曾连续满足0.80 s环境举升资格，但随后在
CARRY中真实双指接触持续消失0.35 s，脚本最终正确记录为`failed_grasp_broke_on_carry`。
当前录像位于`headless_videos/run_20260809_202134_seed20260804/`。该联合改动没有提高这5个
初态的严格成功率；由于同时改变了保持时间和抬升距离，单次联合测试不能判断是哪一项导致差异。

### 16.16 RL抓取语义与PPO奖励重构

RL把原双侧接触确认降级为`pinch`，只有线段相对pinch建立高度上升至少30 mm，并在双侧真实
接触、开度和55 mm中心距离均合格时连续保持0.10 s，才记为`secured grasp`。RL成功要求该
有效抓取下的高度、整线离桌比例和中心距离连续满足0.80 s，不再直接采用底层`ever_success`。

观察从40维扩展到48维，增加左右接触、法向力、pinch、secured grasp、相对抬升和成功保持
进度；pinch后目标切换为实际夹持线段。关节动作尺度从0.08降到0.04 rad/步，夹爪使用
`-0.35/+0.35`滞回选择`ctrl=20/255`，并增加动作变化率代价。

奖励不再按步重复发放接触、抓取和绝对高度奖励，而采用首次接触/pinch/secured grasp事件、
有符号接近与抬升增量、严格保持、25分成功、5分滑脱惩罚和时间/动作代价。默认训练前100万
步把扰动从0.30升至1.50，独立验证始终使用完整1.50并按严格成功率保存最佳模型。

RL无头测试现默认按回合保存MP4和`mjSTATE_FULLPHYSICS`状态NPZ，并保存实际运行模型MJB。
NPZ还包含逐个50 Hz动作、奖励和时间，可直接由现有回放/重渲染工具读取。

## 17. 总结

本项目最终在不修改 Menagerie 官方 Panda 模型的前提下，完成了一个可持续运行的动态柔性线缆抓取演示。实施过程中解决了 XML 路径、插件加载、数组索引、关键帧覆盖、夹爪方向、抓取高度、线缆刚度、可视化时长以及全局抓取辅助失真等问题。

最终系统已经能够展示：线缆连续三维弯曲、Panda抓取前跟踪、平行夹爪闭合、单点吊起、短时保持以及随机多轮重置。默认脚本执行朝桌面中心80 mm并上移20 mm的固定搬运，成功后保持闭爪。
