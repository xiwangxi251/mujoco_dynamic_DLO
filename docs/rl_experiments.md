# RL 基线实验记录

本文档记录 Panda 动态线缆抓取 PPO 基线的代码演进、训练结果、失败模式与后续验证计划。内容来自 Git 历史、服务器训练目录、本地 `outputs/rl` 评估文件以及评估视频观察。

> 更新日期：2026-08-23  
> 当前代码版本：`3506f63 fix(rl): rebalance premature-close rewards to prevent always-open collapse`

## 1. 实验目标

策略需要从完整线缆状态中选择抓取位置和动作，使 Panda 夹爪：

1. 接近线缆中段；
2. 使夹爪闭合方向与局部线缆切向垂直；
3. 让线缆充分进入两指之间后闭合；
4. 形成双指稳定夹持；
5. 抬升并保持线缆，满足严格成功判定。

主要观测、动作与算法配置如下。

| 项目 | 当前设置 |
|---|---|
| 观测 | 99 维：14 个弧长采样点的 TCP 相对位置与速度（84）+ 7 维关节位置 + 7 维关节速度 + 夹爪开度 |
| 动作 | 5 维：base-frame `xyz`、world-z `yaw`、夹爪控制量 |
| 算法 | PPO，MLP `[256, 256, 128]`，ReLU |
| rollout | 每个训练环境 `n_steps=1024` |
| batch / epoch | 512 / 5 |
| 折扣 | `gamma=0.995`，`GAE lambda=0.95` |
| 学习率 | `3e-4 → 3e-5` 线性退火 |
| 熵系数 | `0.01 → 0.001` 线性退火 |
| 默认总步数 | 2,000,000 |

“base-frame xyz / world-z yaw”表示平移增量在机器人基座坐标系中解释，偏航角绕世界竖直轴旋转；这使水平移动和转向不再随末端当前姿态改变。夹爪仍由第 5 个动作维度控制。

## 2. 版本命名与比较范围

主实验链为：

```text
ppo_dlo_baseline_v2 → v3 → v4 → v5 → v6
```

早期目录 `ppo_cable`、`ppo_cable_v2` 属于另一条探索性实现，包含特权目标、8 维关节动作和不同奖励/指标定义。尤其是 `ppo_cable_v2` **不等于**本文的 `ppo_dlo_baseline_v2`，不能按版本号直接横向比较。早期结果只在附录中保留。

## 3. 课程学习设置

课程包含三个场景阶段：

| 阶段 | 场景 | 内容 |
|---|---|---|
| 0 | `id_static` | 静态线缆 |
| 1 | `id_shape_nominal_current` + `id_rigid_l1_nominal` | 形状动态与整体刚体移动分别采样 |
| 2 | `id_combined_l1_nominal` | 形状动态和整体移动同时出现 |

阶段 1、2 的动态难度均按 `1/3 → 2/3 → 1` 递增。因此“动态难度 1/3”取决于当前阶段：阶段 1 会在形状动态或整体移动场景中采样，阶段 2 才同时包含两种动态。

### v2 课程

v2 使用训练内成功次数推进课程，默认每阶段需要 10 次成功，并在移动阶段上用 500k 步逐渐提高难度。现有日志中没有课程阶段切换记录，结合结果判断，v2 实际上一直停留在静态阶段。其较高的部分抓取指标不能解释为已经掌握动态场景。

### v3 及以后课程

课程改为严格评估门控。连续两次评估同时满足以下条件才升级：

- 对齐夹持率 ≥ 50%；
- 稳定夹持率 ≥ 20%；
- 严格成功率 ≥ 10%。

阶段内依次经过 1/3、2/3 和完整难度。v3、v5 均未离开静态阶段；v4 在约 1.5M 步后进入阶段 1、难度 1/3。

## 4. 各版本代码改动

### 4.1 DLO baseline v2 — 完整线缆状态基线

对应提交：`ee9c530 feat: add L1 curriculum PPO baseline`

主要改动：

- 用 99 维完整 DLO 观测替换早期特权目标输入；
- 用 5 维任务空间动作替换 8 维关节动作；
- 引入阻尼逆运动学、线缆中段最近点选择和 L1 课程；
- 建立双指夹持、稳定夹持、抬升和严格保持等分层奖励；
- 动作为 TCP-local `xyz/yaw`。

已确认的问题：姿态对齐使用了错误的手坐标轴语义。奖励倾向让夹爪沿线缆方向排列，而不是让两指闭合方向与线缆垂直。视频中表现为“顺着绳子抓”；即使形成接触，抬升时也更容易滑脱。

### 4.2 DLO baseline v3 — 修正姿态与抬升学习

对应提交：`794d766 fix: improve RL grasp alignment and lift learning`

主要改动：

- 平移动作改为 base frame，偏航改为 world-z，降低末端姿态对动作语义的干扰；
- 按 Panda 两指沿手局部 y 轴闭合的事实重写姿态对齐；
- 使用平面垂直度与距离加权的对齐势能；
- 增强对齐夹持、稳定夹持和抬升奖励；
- 增加 pinch stall、无负载夹持和抬升尝试等惩罚/诊断指标；
- 引入严格评估门控课程；
- 随后在 `c5bcd60` 中加入并行严格评估。

结果上，夹爪已经能与线缆垂直，并且经常能把线缆置于两指之间，但连续夹爪目标没有学出可靠、果断的闭合行为，最终几乎不闭合，也不抬升。

### 4.3 DLO baseline v4 — 捕获感知迟滞夹爪

对应提交：`6992d6a fix(rl): add capture-aware hysteretic gripper control`

主要改动：

- 将策略的连续夹爪动作映射为带迟滞的物理开/闭状态：小于 `-0.35` 闭合，大于 `+0.35` 张开，中间死区保持原状态；
- 定义基于 TCP 距离和姿态对齐的 capture-ready 区域；
- 在正确区域闭合给予奖励，过早闭合给予轻微惩罚；
- 增加 capture-ready、闭合事件和夹爪状态等诊断指标。

该版本解决了 v3 的“不闭合”，是目前已经完成实验中表现最好的版本。但视频显示许多闭合发生在线缆刚到夹爪边缘时，线缆尚未充分进入指间，导致浅夹持、夹不紧和抬升滑脱。

### 4.4 DLO baseline v5 — 插入深度闭合门控

对应提交：`756c591 fix(rl): gate gripper closure on cable insertion depth`

主要改动：

- 在夹爪局部坐标中定义指间捕获走廊；
- 增加纵向、横向和插入深度条件：纵向容差 12 mm、横向容差 10 mm、指尖偏移 8.5 mm、有效插入深度约 6.5–17.5 mm；
- 只有线缆居中且充分进入两指之间才标记 capture-ready；
- 增加局部偏移、插入深度和过早闭合事件日志；
- 将过早闭合事件惩罚设为 `-0.25`，持续错误闭合设为 `-0.003/step`。

几何门控方向正确，但奖励尺度失衡。训练初期随机策略频繁触发一次性 `-0.25`，使 PPO 很快学成“始终张开”以规避惩罚，导致策略塌缩。

### 4.5 DLO baseline v6 — 重平衡过早闭合奖励

对应提交：`3506f63 fix(rl): rebalance premature-close rewards to prevent always-open collapse`

主要改动：

- 保留 v5 的指间捕获走廊和插入深度门控；
- capture-ready 时保持张开的惩罚改为 `-0.001/step`，推动及时闭合；
- 过早闭合事件惩罚从 `-0.25` 降至 `-0.04`；
- 持续过早闭合惩罚从 `-0.003/step` 降至 `-0.001/step`；
- 每回合过早闭合事件惩罚总额上限设为 `0.50`；
- 新增过早闭合事件比例指标和惩罚上限回归测试。

集成测试共 17 项通过。该版本只完成了代码修正，尚无完整训练结果，不能提前判断是否恢复 v4 的抓取能力。

## 6. 失败模式演进

```text
v2：姿态轴语义错误
    → 夹爪沿线缆抓取
    → 接触后易滑脱，难以抬升

v3：姿态已修正
    → 线缆能进入夹爪
    → 连续夹爪控制未学会果断闭合

v4：迟滞开闭解决不闭合
    → 闭合时机偏早、插入过浅
    → 弱夹持和滑脱

v5：增加插入深度门控
    → 过早闭合惩罚过强
    → 策略通过始终张开规避惩罚

v6：保留几何门控并重平衡奖励
    → 等待实验验证是否能同时做到“深入后及时闭合”
```

### v5 奖励塌缩的数值证据

- 训练初段夹爪闭合比例约 49.7%，末段仅约 1.1%；
- capture-ready 比例末段约 20.1%，但 capture-close 事件仅约 0.03%；
- 第 5 动作维度均值最终约 `+0.823`，明确偏向张开；
- rolling pinch 峰值约 42%，最终约 1%；aligned pinch 峰值约 22%，最终为 0；
- v5 初期均值回报约 `-48.85`，v4 同期约 `-14.08`，相差约 `-34.77`。

随机初期的夹爪切换比例约为 0.361。若其中约一半是闭合事件，每回合 750 步，则事件惩罚量级约为：

```text
0.361 × 0.5 × 750 × 0.25 ≈ 33.8
```

这与 v5 相对 v4 的初期回报下降约 34.77 高度吻合。因此，“事件惩罚主导优化并诱发始终张开”是由代码和训练指标共同支持的解释，而不只是视频猜测。

## 7. 结论

1. 服务器与本机差异不是 v3–v5 性能变化的首要解释。本地确定性回放重现了服务器指标对应的行为，且每次退化都与动作接口或奖励变化一致。硬件与并行调度可能造成小幅随机差异，但不足以解释 v5 从有效闭合变成几乎始终张开。
2. v2 的主要瓶颈是错误姿态目标；v3 的主要瓶颈是闭合控制；v4 的主要瓶颈是闭合过早和插入过浅；v5 的主要瓶颈是惩罚尺度导致的策略塌缩。
3. v4 证明“正确姿态 + 迟滞夹爪”能够学习出抓取和抬升，也是当前最强已验证版本。
4. v5 的插入深度几何不应删除；应保留几何约束并修正奖励比例，这正是 v6 的设计。
5. 当前证据只有单个训练 seed，且严格评估通常为 20 回合、本地单场景仅 10 回合。成功率差异需要更多 seed 和更大评估样本才能形成统计结论。

## 8. v6 验证计划

### 8.1 训练命令

使用当前默认的 2M 步、CPU、50 回合常规评估和 50 回合确认评估，仅覆盖服务器并行数：

```bash
panda-cable-rl-train \
  --workers 48 \
  --eval-workers 10
```

若要与 v3–v5 的 20/20 评估设置完全一致，应显式加入：

```bash
  --eval-episodes 20 \
  --eval-confirmation-episodes 20
```

当前默认输出目录为 `outputs/rl/train/ppo_dlo_baseline_v6`。

### 8.2 必看指标

v6 训练中不应只看总 reward，应同时检查：

- `gripper_closed_fraction`：不能像 v5 一样衰减到接近 0；
- `capture_ready_fraction`：确认策略确实进入正确几何区域；
- `capture_close_event_fraction`：ready 后应出现闭合；
- `premature_close_event_fraction`：应下降，但不能靠始终张开归零；
- `pinch / aligned_pinch / loaded_lift / stable_grasp / strict_success`：必须形成逐层转化；
- 课程阶段：确认静态能力稳定后再进入动态难度 1/3。

建议在 300k–500k 先做一次中期审计。如果 capture-ready 已上升、闭合比例却持续下降，应立即停止训练并检查奖励比例，无需等满 2M 步。

### 8.3 完整评估

训练完成后，对 `best_model.zip` 在四个固定场景各运行 10 回合，并保存视频和逐回合诊断。比较时至少报告：

- 严格成功率；
- never pinch、pinch-not-secured、physical slip、open during contact loss；
- 首次闭合时的局部纵向/横向偏移和插入深度；
- 从 pinch 到 loaded lift、stable grasp、strict success 的转化率。

## 9. 比较限制

- 训练严格评估使用“当前课程分布”，本地四场景测试使用固定单场景，两者成功率不能直接等同；
- v2、v4 的结果包含最佳 checkpoint，而 v3、v5 主要分析 final checkpoint；
- 不同版本的评估器和诊断字段有演进，缺失字段不能按 0 处理；
- 少数本地评估父目录名称与实际 checkpoint 不一致，应以 `manifest` 中记录的模型路径为准；
- 视频观察用于解释指标，但结论应尽量由事件日志、逐回合结果和物理状态共同确认。
